## ADDED Requirements

### Requirement: HK Trend V4 Final-Design Alignment
The HK trend official F' data product SHALL use a V4 payload that aligns cached final-design health/state fields into the official `.fdp` path while preserving the `HkTrendRecord` product record name and id.

#### Scenario: V4 payload is generated from cached state
- **WHEN** `HkTrendProductProducer` captures a state snapshot
- **THEN** it SHALL serialize a `HkTrendRecord` id `0` payload with `version = 4`
- **AND** the payload SHALL include the existing V3 HK trend fields plus provider-backed cached gaps for ADCS attitude details, GPS time/motion fields, governed storage roots, COMM band, CSP counters, radio/UART link stats, and boot metadata
- **AND** it SHALL use the existing cached snapshot source rather than polling subsystem transports directly

#### Scenario: Missing subsystem values remain explicit in V4
- **WHEN** one subsystem snapshot is missing during HK trend capture
- **THEN** the V4 record SHALL set that subsystem validity flag to false
- **AND** it SHALL NOT silently present neutral numeric values as known real measurements

#### Scenario: Historical backward decode is not claimed for V4
- **WHEN** reviewers evaluate this change
- **THEN** the evidence SHALL treat V4 `.fdp` files generated by the current dictionary as the decode target
- **AND** it SHALL NOT claim that old V1, V2, or V3 `.fdp` files decode with the V4 dictionary

### Requirement: Default Hosted CCSDS S-band FDP Parity
The hosted default CCSDS S-band data-product path SHALL prove that a generated HK `.fdp` can be cataloged, transmitted to GDS, byte-matched, and decoded.

#### Scenario: Default hosted CCSDS S-band receives byte-matched FDP
- **WHEN** the hosted CCSDS S-band FDP parity probe runs after a fresh build
- **THEN** it SHALL use the default `OBC` binary and `OBCApp.*` command namespace
- **AND** it SHALL route GDS traffic through CCSDS framing, `ground_ttc_gateway` raw relay, S-band TCP, and `sband_comm_csp_node` node `5`
- **AND** it SHALL generate one or more HK trend `.fdp` files under `<runtime-root>/data-products/`
- **AND** it SHALL build the `DpCatalog` catalog and start catalog transmit
- **AND** it SHALL find a GDS-received `.fdp` file that byte-matches the matching source runtime file

#### Scenario: Default hosted CCSDS S-band received FDP decodes
- **WHEN** a byte-matched GDS-received `.fdp` file is available from the default hosted CCSDS S-band path
- **THEN** the probe SHALL decode the received file with the current dictionary
- **AND** the decoded output SHALL identify the HK trend product record and `version = 4`

#### Scenario: HK ring fallback is not promoted to official catalog
- **WHEN** the V4 `.fdp` evidence is recorded
- **THEN** it SHALL describe `DpCatalog` as the official `.fdp` catalog/index surface
- **AND** it SHALL describe `HousekeepingArchive` and `hk/index.csv` as bounded transitional fallback with separate slot/generation semantics
